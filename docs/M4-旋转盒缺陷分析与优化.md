# M4 旋转盒：缺陷分析、对照实验与修复

本文记录 2026-09-23 对 30° 旋转盒失败的独立审计。BabelSim 源码仅作为读取契约检查，未修改。M4 总状态仍为 `in_progress`；通过当前旋转盒与球面测试不等于完整 M4 质量验收。

## 1. 可复现输入和失败现象

输入：`acceptance/evidence/m4-rotated/project.json`。外域为 `[0,2]^3 m`，实体为边长 1 m、绕中心 z 轴旋转 30° 的盒子。背景为 `8^3`，正式表面尺寸 0.015625 m。原失败输出含 58,016 个单元、295,992 个面、113,232 个点。

原读取器报错：`polyhedral cell face area vectors do not close`。这只是最后暴露问题的检查，不是最早的算法缺陷。失败文件的 SHA-256 与完整审计计数保存在 `acceptance/evidence/m4-rotated/baseline-audit.json`。

独立审计分开检查原始面环、原始面积向量、读取器初始中心的方向判据，以及此算例已知的解析 CAD 平面：

| 检查 | 原失败网格 |
|---|---:|
| 原始单元边使用次数/方向不匹配 | 55 个单元 |
| 原始面积向量不闭合 | 0 个单元 |
| 面方向与单元点均值不相容 | 342 个单元 |
| 预计被读取器翻转的面 | 598 个面 |
| 预计翻转后面积不闭合 | 342 个单元 |
| 壁面顶点偏离解析盒面 | 0 个面 |
| 壁面法向与解析流体外法向相反 | 0 个面 |
| 壁面 owner 的所有顶点均位于该面的外侧 | 598 个面 |

`tools/audit_rotated_box.py` 的多边形面积向量使用叉积恒等式。读取器翻面是按其初始点均值所作的预测；不能替代真实读取器对多边形三角剖分、体积、面心距的检查。该脚本仅适用于这里的中心 `(1,1,1)`、边长 1、z 轴 30° 盒子，不能用作通用 CAD 距离工具，也没有证明不存在面自交。

## 2. 缺陷和因果链

**缺陷 A：面关联丢失了原始壁面的方向约束。**

原实现先把每个边界点投影到最近的裁剪 CAD 面，再对点的标签进行多数投票，推导边界面的关联。尖棱附近，垂直阶梯壁面上的底部顶点可能离盒子底面最近，而同一壁面的其他顶点关联侧面。随后按这些标签拆面，会制造本不应属于该体单元的底部水平壁面。

正式失败网格中 598 个面具有正确 CAD 位置和流体外法向，但 owner 的全部点都在外侧，是直接的几何反证。不能把它解释为只是读取器选错了中心，或只是面环顺序不佳。原始壳的有向体积仍可能为正，局部错误会在总和中抵消；点到 CAD 的距离也无法识别错误的体域归属。

**缺陷 B：捕捉半径和最终几何残差混用。**

原有共享棱/角点关联的接受条件是：原始点到特征的距离不大于最终 CAD 残差容限。对于阶梯网格，捕捉所需位移是局部网格尺度，最终误差应小得多。原逻辑通常未能在需要时把点移到共享特征。

但简单放大这个半径并不能修复缺陷 A。单变量试验把半径改为表面尺寸后，粗网格出现了 `1716 1721 1349 1722 1721` 的非简单面环。该改动已撤回，日志为 `feature-radius-only.log`。

**缺陷 C：退化面删除后的边分段没有完全传播。**

一侧使用 `A-B`，另一侧使用 `A-P`、`P-B`，其中 P 共线且位于线段内部。几何面积可以闭合，但拓扑边不配对。之前只从被删除面传播中间点，遗漏了其他相邻面中的分段。独立 C++ 修复在原失败网格上插入 55 个面环节点，使不闭合单元由 55 降为 0，点坐标、单元数和面数未变；342 个方向异常单元未减少。对照记录为 `conformance-ab.log`。

**缺陷 D：接受判据不足。**

旧的线搜索只检查总有向体积及单向 CAD 采样误差。严格模式每次仍把边界点移到最终位置，只缩小内部点位移。它不能保证局部几何有效性。报告还把尚未计算的变形后 Jacobian、非正交度和偏斜度填写为理想值，容易误导验收。

## 3. 已实现的优化

1. 对全部由平面 B-Rep 面组成的流体域，先用原网格面的外法向筛除朝向不相容的 CAD 平面，再在候选裁剪面中选择距离最近者。关联保存在面上，不再由独立最近点投影反推。
2. 单一支撑面的顶点投影到该面；多个支撑面的顶点投影到它们真正共享的 B-Rep 棱或角点。捕捉半径取相邻边最大长度的两倍，最终 CAD 容限保持原值。如果多个支撑面无公共特征或超出捕捉范围，明确失败，要求局部拓扑重建。
3. 拆面时优先使用已确定的面关联；在共享特征上的点允许同时属于多个支撑面，不因为单一顶点标签任意制造新的壁面片。
4. 共线边一致化只插入已有的、属于 incident cell 的内部线段点；不移动点、不删除单元。将同一条边的分段同步应用于所有使用该边的面。之后重新检查边使用次数和方向。
5. 增加生成端单元壳检查：每条单元边使用两次且方向相反、面积向量闭合、面方向与读取器初始点均值相容。检查失败时在生成端返回单元编号和计数，而不是输出看似接受的结果。
6. 尚未计算的变形后质量指标写为 JSON `null`，并标记 `full_cfd_profile_evaluated=false`。自适应网格的非正交度/偏斜度也不再无条件填 0。

实现位于 `src/core/fluid_domain.cpp` 和 `src/core/polyhedral_audit.cpp`。平面域识别基于 OCCT 曲面类型，没有针对盒子坐标或 30° 角度写特例。**一般曲面与曲面尖棱仍走原路径，不在本次已修复范围内。**

## 4. 研究依据与适用边界

- [Cadence/NUMECA: Generic Gas Turbine Combustor](https://www.cadence.com/content/dam/cadence-www/global/en_US/documents/tools/system-analysis/paper-generic-gas-turbine-convertor.pdf)：公开资料描述 HEXPRESS 的 volume-to-surface、snapping 和 optimization 思路。这里保留笛卡尔体网格起步、后续捕捉几何和改善质量的路线，不声称复现其未公开的专有算法。检索获得官方 PDF 的索引摘要，直接抓取 PDF 超时，因此未据此推断内部实现细节。
- [OpenFOAM 官方 snappyHexMesh 用户指南](https://www.openfoam.com/documentation/user-guide/4-mesh-generation-and-conversion/4.4-mesh-generation-with-the-snappyhexmesh-utility)：捕捉容限按局部最大边长定义，`errorReduction` 控制问题点的位移回退。这支持把捕捉范围与最终几何残差分开。该站正文抓取 403，采用官方搜索索引中对应参数说明。
- [OpenFOAM 2.3.0: snappyHexMesh](https://openfoam.org/release/2-3-0/snappyhexmesh/)：显式特征边是独立的几何约束，可优先捕捉不同特征类型，支持将特征关联从普通逐点投影中独立出来。
- [Sandia: Hexahedral Mesh Untangling](https://www.sandia.gov/research/publications/details/hexahedral-mesh-untangling-2000-12-13/)：结点优化并非能修复任意坏拓扑。先修复关联和拓扑，再做几何优化，不能把问题全部交给 Laplace 平滑。
- [Sandia/CUBIT: Untangle](https://www.sandia.gov/files/cubit/15.4/help_manual/WebHelp/mesh_generation/mesh_modification/mesh_smoothing/untangle.htm)：解缠和形状改善是不同阶段，解缠成功仍可能需要后续质量优化。
- [CGAL Polygon Mesh Processing 官方文档](https://doc.cgal.org/5.6/Polygon_mesh_processing/index.html)：自交、定向和闭合体检查是独立谓词。当前新增检查是必要条件，不是完整自交和重叠检测的替代。

本实现的朝向约束面关联是结合这些原则与本项目失败证据作出的工程设计，不是从上述资料逐字复制的 HEXPRESS 算法。

## 5. 复现与后续验收

本轮已完成的验证结果：

| 验证 | 结果 |
|---|---|
| 共享边拓扑修复的独立 A/B | 原文件 55 个不闭合单元降至 0；几何异常仍为 342，证实是两种缺陷 |
| 15° / 30° / 45° 粗网格特征回归 | 均通过当前 BabelSim 读取与 validate |
| 原正式 30°，58,016 单元 | 生成、真实读取、独立解析盒审计全部通过 |
| 原正式网格的边不配对/方向异常/预计翻面 | 全部为 0 |
| 正式网格的严格 hex / polyhedron | 45,688 / 12,328，hex 占约 78.75% |
| 正式网格采样 CAD 残差 | 4.9651e-16 m；原容限 3.4641e-4 m 未放宽 |
| 正式网格流体体积相对误差 | 6.0904e-15 |
| M4 现有基础测试 | 通过，包括球面和正式旋转盒；不是完整 M4 通过 |

正式新网格为 295,388 个面、112,526 个点，未删除退化面。错误面关联修正后，不再依赖删除那些错误面片来勉强输出旋转盒。结果文件哈希及各项统计见 `oriented-support-formal-audit.json`，真实读取日志见 `formal-reader.log`，生成器报告见 `oriented-support-formal-report.json`。这里的距离仍是采样残差，不能等同于一般几何的双向 Hausdorff 误差。

```bash

make -j4 build/debug/bin/m4_domain_test
build/debug/bin/m4_domain_test
build/debug/bin/babelmesh generate acceptance/evidence/m4-rotated/project.json \
  --cad-staircase --out /tmp/babelmesh-m4-oriented-formal
```

`test-m4-features` 在表面尺寸 0.0625 m 下检查 15°、30°、45° 三个角度，使用当前 BabelSim 源码编译并调用其真实读取器。`m4_domain_test` 包括原正式 30° 旋转盒，以及既有分类、连通域、轴对齐盒、球面等检查。新增壳测试覆盖面积闭合却边不匹配、修复幂等、拒绝离线点以及反向面的情况。

M4 仍需：曲面特征拓扑关联、真正分阶段的边界位移与质量回退、一般局部重构、双向 CAD 距离、面内误差采样、真实 Jacobian/非正交度/偏斜度、圆柱/圆角/薄尾缘/间隙算例及三级收敛。不得用当前旋转盒读取通过替代这些验收。

## 6. 本轮质量优化（2026-09-23）

采用 BabelSim 自身 `faceCentre/faceArea/cellCentre` 对导出网格计算质量，确认早先壁面按细小三角子面输出使 skew 被系统性放大：三角面心离 owner-neighbour 中心连线较远，且以 `sqrt(|Sf|)` 归一后产生高 skew。独立把同一 owner/neighbour 之间连续、共享边、近共面的子面合并成一个公共面，不改变节点坐标。相邻壁面只按面法向与 CAD 平面关联，不把它们混到同一面；内部面允许相对翘曲 0.05 的合并容差，并继续通过真实读取器及闭壳检查。

另在 CAD 相交单元外扩两层 `surface_size` 作为贴壁缓冲区，使 2:1 粗细交界不紧挨 CAD 壁面。正式旋转盒网格由 58,016 个 cell、109,080 个超限三角内部面，优化为 133,728 个 cell、0 个超限内部 skew 面；两个版本不具同一单元数，质量比较用于定位机制而非固定拓扑 A/B。正式优化网格最大非正交度 31.552°、P99 27.449°，内部 skew 最大值 0.244485、P99 0.236957。15°/30°/45°快速旋转盒中，P99 skew 分别为 0.23686、0.23676、0.23773，三个面向指标均达现有 profile 门槛并通过 BabelSim reader。

共线四节点面也可能实际只有三个非共线角点。现在面合并后按真实转角把这类单元从严格 hex 分类降为 polyhedron，保留悬挂点和闭壳拓扑；不会将负 Jacobian 取绝对值。独立分析正式 VTU 中全部 512 个 Jacobian 低于 0.1 的 hex 后，512/512 均与近共线四边面相邻；最新分类容差将此种几何退化单元导出为多面体。最新重生成将 512 个近共线单元改为 polyhedron，剩余 111,360 个 regular hex 的最小 scaled Jacobian 为 0.703808，低于 0.1 的数量为 0。证据位于 `acceptance/evidence/m4-rotated/optimized-formal/`。

命令：

```bash
make -j4 test-polyhedral-audit test-m4-features
build/debug/bin/babelmesh generate acceptance/evidence/m4-rotated/project.json \
  --cad-staircase --out /tmp/m4-formal-optimized
build/debug/bin/m4_solver_quality_probe /tmp/m4-formal-optimized/mesh.bsm
python3 tools/audit_hex_jacobians.py /tmp/m4-formal-optimized/mesh.vtu \
  --bsm /tmp/m4-formal-optimized/mesh.bsm
```

这次实现覆盖旋转平面锐边案例的质量改善，不等于 M4 全门禁：质量回滚尚未包含 skew、非正交度和 Jacobian 条件；CAD 曲面到网格的反向误差、全面自交检查、圆柱/圆角/间隙/尾缘测试和三级曲率收敛仍未验收。详见 `acceptance/suite.json` 的 M4 状态。
