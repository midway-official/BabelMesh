# BabelMesh

BabelMesh is a C++17 three-dimensional unstructured CFD mesh generator. The
planned workflow starts from a uniform Cartesian hexahedral grid, adapts it to
CAD and requested size fields, inserts boundary layers, validates the result,
and exports BabelSim's face-based `BABELSIM_MESH 3` format.

The project is being implemented in acceptance-gated stages. M0 through M3
have passed their recorded gates. M4 currently supports CAD fluid-domain
extraction and staircase snapping, with a quality-tested planar rotated-box
path; general curved-feature and full M4 quality acceptance remain in progress.
The mesh writer targets BabelSim's
`BABELSIM_MESH 3` face-based format; the current gate ledger and verified
capabilities are recorded in
[`docs/BabelMesh-研究与实施规划.md`](BabelMesh-研究与实施规划.md).

## Build with GNU Make

Requirements: GNU Make 4+, a C++17 compiler, Python 3 and the Python
`jsonschema` package. CAD and project parsing use OCCT 7.5, Eigen 3.4, and
nlohmann/json 3.10.5. `make test` also compiles the current BabelSim mesh reader
from the sibling `../BabelSim` checkout; override `BABELSIM_ROOT` if it is stored
elsewhere. The dependency inventory and licenses are recorded in
[`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

On Ubuntu 22.04, the expected package set is:

```bash
sudo apt install make g++ python3 python3-jsonschema nlohmann-json3-dev \
  libeigen3-dev \
  libocct-foundation-dev libocct-modeling-data-dev \
  libocct-modeling-algorithms-dev libocct-ocaf-dev \
  libocct-visualization-dev libocct-data-exchange-dev
```

Build and run the contract tests:

```bash
make debug -j4
make test -j4
make release -j4
```

`build/debug/bin/babelmesh --help` shows implemented commands. A command that
belongs to a later stage exits with a non-zero status and says so explicitly; a
placeholder does not count as a working meshing feature. `make clean` removes
only the local `build/` output directory.

For the current M4 development path, run:

```bash
build/debug/bin/babelmesh generate acceptance/evidence/m4-rotated/project.json \
  --cad-staircase --out /tmp/babelmesh-m4
```

`sizing.surface_buffer_layers` defaults to 2 and accepts integers from 0 to 8.
It refines a band around CAD surface-intersecting cells to move coarse/fine
transitions away from snapped walls. Reports expose the selected value and the
number of consolidated faces. This option does not itself establish full M4
acceptance; check `acceptance/suite.json` for the required gate status.

`quality.max_surface_deviation_m` optionally sets an explicit CAD surface
deviation tolerance in **meters**, independent of the project's input units.
For example, `0.001` permits 1 mm of sampled surface deviation. Without this
the default is `max(domain_diagonal * 1e-4, 1e-9)`, independent of the mesh
size. The report records both the effective tolerance and whether it was
overridden. The tolerance constrains CAD fitting only; strict cell-volume,
Jacobian, non-orthogonality and skewness gates remain independent.

The public Hexpress workflow follows the same separation: a global Cartesian
cell size, then local boundary controls for uniform size, edge proximity, and
curvature, followed by separate viscous-layer settings and mesh-quality
inspection ([Cadence Fidelity/Hexpress tutorial](https://www.cadence.com/content/dam/cadence-www/global/en_US/documents/tools/system-analysis/introductory-tutorial-guide-fidelity.pdf)).

For CAD boundary meshing, `sizing.surface_size` must be provided explicitly in
project length units. It is the **maximum characteristic edge length (the
longest physical edge) for cells in the CAD boundary-refinement band**, not the CAD fitting tolerance or a requested
surface tessellation spacing. The octree refines all three axes together, so a
single scalar cap accurately describes the current algorithm. It must be no smaller
than `minimum_size` (the floor for adaptive splits; a user-defined background
grid may already be finer), reachable at `max_level`, and within the configured cell
and memory budgets; incompatible requests fail with a diagnostic. Because the
octree only has dyadic levels, the realized boundary-cell edge can be smaller
than the requested cap by up to one refinement step; `minimum_size` prevents
that step from going below the configured floor. Global, surface, and
overlapping local size sources are combined by taking the finest active target.
Use box, distance, curvature, or gap sources when only selected parts need
finer cells.

For a `curvature` sizing source, `target_size` is always the requested cell
size. `region.max_radius` separately selects CAD faces whose sampled radius of
curvature is at or below the specified value. This mirrors Hexpress's public
separation of uniform surface size, edge proximity, curvature resolution, and
viscous-layer controls. The current curvature selector samples each trimmed
face at a 3-by-3 UV pattern, so it is a coarse local sizing aid rather than a
high-order curvature guarantee.

CLI exit status: `0` for help/version or successful commands, `2` for an unknown
command or option, and `3` when a recognized command belongs to a later stage.
Implemented commands reserve `1` for runtime or input failures and provide
entity-specific diagnostics.

See [`docs/BabelMesh-开发Prompts.md`](BabelMesh-开发Prompts.md) for the
stage-by-stage implementation and acceptance prompts.
